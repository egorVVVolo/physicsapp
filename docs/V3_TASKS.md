## Разбор (26 нояб.)

### Общее впечатление
Основа сильная: на экране один фокус, фигуры чистые и честные (по модели), у каждого неверного варианта есть подсказка, загадки урока правда интересные. Главная проблема — **задания проще, чем выглядят**: почти в каждом можно ответить, не понимая физики. Остальное — полировка.

## Чек-лист урока (для задач L1–L12)

Каждый пункт 1–8 проверяет тест (задача P1), пункты 9–12 — вручную, глазами, по скриншотам.

1. **unit** — у каждой клетки каждого build (история, Skill check, части examCard) хотя бы одна неверная фишка с той же единицей. Неверная фишка — названная ошибка из банка ошибок, её число считается функцией из `src/physics/`, у неё есть `hint`. Исключение: клетка для g (`9.81 N kg⁻¹`).
2. **prompt** — в тексте вопроса build нет `=`, `÷`, `×` (формула не подсказана словами).
3. **choose** — в истории хотя бы один build с `choose`: 2–3 уравнения, неверные — реальные ошибки (например, `v = d ÷ t` вместо `v = s ÷ t`, `Ek = mv²` без ½, `σ = F ÷ d²`), у каждого `hint`.
4. **after-predict** — экран сразу после прогноза (третий) не `text`.
5. **revisit** — экран с `revisitOf` стоит не раньше `0.6 × длина истории`, после него не больше 3 экранов.
6. **ending** — последний экран истории не `text`. Обычно это вопрос на перенос (`choice` или `tapFig`): та же идея в новой ситуации, без чисел из урока.
7. **spot** — в двух spotError урока (история и Skill check) ошибка в **разных** позициях; хотя бы в одном из них ошибка в первой или последней строке. В каждом spotError хотя бы две строки с числами.
8. **words** — абзац текстового экрана ≤ 40 слов, текст вопроса ≤ 35 слов. Не укладывается — сокращай текст, правило не трогай.
9. **Рисунок прогноза** показывает все данные загадки (длины, массы, скорости — подписями на листе), прогноз отвечается без памяти о прошлом экране.
10. **Рисунок не выдаёт ответ** до Check: на build нет подписи с результатом, который просят собрать; на estimate нет стрелки в натуральную длину.
11. **Уровень** — как на экзамене (Intermediate): хотя бы один шаг в уроке требует двух действий подряд (например, сначала разложить, потом подставить; сначала знак, потом формула). Никаких вопросов, где ответ есть в тексте того же экрана.
12. **Минимализм** — на экране не больше одного нового термина; картинка без лишних деталей (правило 23 нояб.: цвет только у тел из вопроса и у людей).

Длина урока остаётся 12–16 экранов + 4 Skill check (правила v3 не меняются).

### P1 Правила полировки в тесте

**Цель.** Пункты 1–8 чек-листа проверяются автоматически. Пока урок не переделан, правила к нему не применяются (как `REVISED` в версии 2).

**Читать:** `src/content/rules.test.ts` (функция `v3Problems`, синтетический урок в конце), `src/content/types.ts` (`BuildScreen`, `SpotErrorScreen`, `ExamCardScreen`, `TextScreen`).

**Шаги.**
1. В `rules.test.ts` новая функция `polishProblems(lesson: Lesson): string[]`, рядом с `v3Problems`. Каждое правило — строка вида `unit: <screen id>.<box>` и т. п. Единица фишки:
   ```ts
   /** "−200 m" → "# m", "9.81 N kg⁻¹" → "# N kg⁻¹", "2.0 × 10⁻³" → "#" */
   const unitOf = (label: string) => label.replace(/[−\-+]?[\d.,]+(\s| )?(×\s?10[⁻⁰¹²³⁴⁵⁶⁷⁸⁹]+)?/g, '#').replace(/\s+/g, ' ').trim();
   ```
   Build-экраны собирай из истории, Skill check и частей examCard (`part.kind === 'build'` → `part.build`).
2. Правила: `unit`, `prompt`, `choose`, `after-predict`, `revisit`, `ending`, `spot`, `words` — точно как в чек-листе выше (пункты 1–8). Для «строк с числами» в `spot`: строка содержит цифру.

### S1 Build: перенос уравнения, видимые фишки, инструкция один раз

**Цель.** Уравнение не рвётся между знаком и клеткой; все фишки видны над кнопкой Check; длинная инструкция — только на первом build урока.

**Шаги.**
1. `lineItems`: знак действия (`×`, `÷`, `+`, `−`, `=`) склеивается со **следующим** элементом в один неразрывный кусок (как уже сделано для `²` и скобки). Проверка: «Power and efficiency», экран `winch` — `÷ t` переходит на вторую строку вместе, `÷` не висит в конце первой.
